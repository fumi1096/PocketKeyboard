# 手机模拟电脑键盘 · 需求确认书 v0.1

> 状态：**已确认 v1.0（2026-11-09，按默认值全选）**　｜　开发进度：M1 通路 + M2 主体键盘已实现并编译出 APK，待真机验证
> 日期：2026-11-09　｜　关联文档：《手机蓝牙HID键鼠-开源方案调研.md》
> 一句话：把 Android 手机变成一台**电脑级蓝牙键盘**——全中文界面、横屏 104 键、Ctrl/Alt/Shift/Win 齐全、F1–F12 与组合键可用，电脑端**零安装**，蓝牙配对一次即用。

---

## 1. 技术路线结论（先对齐"完全模拟"的边界）

| 路线 | 电脑端 | Android 可行性 | iOS 可行性 | 结论 |
|---|---|---|---|---|
| **经典蓝牙 HID（BR/EDR）** | 零安装，系统蓝牙直接认 | ✅ 系统 API `BluetoothHidDevice`，Android 9+，免 Root | ❌ 不开放设备端 | **主路线** |
| BLE HID over GATT（HOGP） | 零安装（看主机支持） | 需自建 GATT Server，可行但复杂 | ✅ 需开发者证书 | 后续可选 |
| WiFi + 电脑端小工具 | 要装程序 | ✅ | ✅ | 兜底方案 |
| USB HID（手机当 U 盘式键盘） | 零安装 | ❌ 需 Root/特殊内核 | ❌ | 放弃 |

**结论：主路线 = Android 9+ 经典蓝牙 HID，电脑端零安装。**

### 1.1 能做到的（"完全模拟"的真实上限）

- 标准 HID 键盘全部键位：字母数字、符号、Esc/Tab/Enter/Backspace/CapsLock、**F1–F12**、方向键、Ins/Del/Home/End/PgUp/PgDn、**独立小键盘（NumLock 状态可切）**。
- **修饰键 8 个**：左/右 Ctrl、Shift、Alt、**Win（macOS 上即 Command）**。
- **任意组合键**：多指同时按住即可发 Ctrl+C、Ctrl+Alt+Del、Ctrl+Shift+Esc、Alt+Tab、Win+L、Alt+F4 等（HID 是硬件路径，Ctrl+Alt+Del 有效）。
- 媒体键（播放/暂停/上一曲/下一曲/静音/音量±）、系统键（电源/睡眠/唤醒）。
- 电脑端（Windows / macOS / Linux / Android TV / iPadOS）在系统蓝牙里配一次就显示为普通"键盘"，**不装任何软件**。
- 手机侧界面全中文，可自定义布局、皮肤、按键大小。

### 1.2 做不到的（必须提前说清，避免验收争议）

| 限制 | 说明 |
|---|---|
| 进 BIOS / UEFI / 开机密码界面 | 系统起来后才加载 HID 驱动，物理上不可能 |
| 同时控制多台主机 | HID 设备一次只连一台，切换需断开重连 |
| 手机屏幕熄灭后盲打 | 触屏 UI 需要亮屏；熄屏=没法点 |
| 直接向电脑"上屏中文" | 纯 HID 只发按键，中文必须靠电脑自己的输入法 |
| iPhone 上用经典 HID | iOS 只开放 BLE HOGP，需 Mac + 证书，不在本期 |
| 原样复制苹果 Fn/亮度/背光键 | 属 Apple 私有 usage，标准 HID 无法通用 |

### 1.3 需真机验证的风险点

- 个别国产 ROM（MIUI/HyperOS、ColorOS、OriginOS）蓝牙栈可能**不暴露 HID Device profile**；
- 老旧电脑蓝牙适配器（BT 2.1/3.0）配对偶发失败；
- 部分主机对**自定义 NKRO 报文**兼容性差（需要 6KRO 兜底）。

## 7. 技术实现要点（概要，不展开代码）

- **权限**：`BLUETOOTH_CONNECT`（Android 12+ 运行时）、`BLUETOOTH_ADVERTISE`（可发现）、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`POST_NOTIFICATIONS`。
- **注册**：`BluetoothAdapter.getProfileProxy(ctx, listener, BluetoothProfile.HID_DEVICE)` → `BluetoothHidDevice.registerApp(SdpSettings, QosSettings, appData, callback)`；`SdpSettings` 填设备名、描述、厂商、subclass（0xC0 组合设备）、HID Report Descriptor。
- **三个 Report**：ID1 键盘（修饰字节 + 6 键码 / 或 NKRO 位图）、ID2 鼠标（按键 + X/Y + 滚轮）、ID3 Consumer（媒体键）。可选 ID4 System Control（电源/睡眠）。
- **发送**：`sendReport(device, reportId, bytes)`。
- **必须实现的回调**：`onGetReport` 回 `reportData(...)`、`onSetReport`/`onSetProtocol` 回成功、`onInterruptData` 容错、`onVirtualCableUnplug` 更新状态；否则部分主机会拒绝连接。
- **布局换算**：发的是 HID usage（物理位置码），主机键盘布局决定输出字符 → 提供"布局预设"（中文-美式 / 英文-美式 / 英式 / 德式）；P1 提供"字符模式"按主机布局换算，保证符号正确。
- **技术栈建议**：Kotlin + Jetpack Compose，单 Activity，MVVM；minSdk 28 / targetSdk 最新；横屏锁定键盘页。
- **代码结构**：`hid/`（HidManager、ReportDescriptor、KeyMap）、`ui/`（KeyboardScreen、KeyCap、Touchpad、SettingsScreen）、`domain/`（KeyEvent 模型、组合键状态机、宏）。

## 10. 前置条件（环境，重要）

- 当前工作区在 `E:\手机模拟键盘app`，命令行沙箱无法取得写权限（`SetNamedSecurityInfoW ... grantWrite` 失败），**文件读写正常，但 `pwsh`/`gradle`/`adb` 等命令跑不起来**，无法编译打包。解决方案（二选一，见决策 D9）：
  1. 把本会话切到**完全权限**；
  2. 把工程挪到 NTFS 本地盘（如 `C:\` 或 `D:\`）。
- 需要 Android SDK（建议 Android Studio，含 JDK 17、SDK Platform 34/35、build-tools）。

### 附录 A：HID 键码（Usage Page 0x07）速查

| 类别 | Usage 范围 |
|---|---|
| 字母 A–Z | 0x04–0x1D |
| 数字 1–0 | 0x1E–0x27 |
| Enter/Esc/Backspace/Tab/Space/CapsLock | 0x28/0x29/0x2A/0x2B/0x2C/0x39 |
| 符号 `- = [ ] \ ; ' ` , . /` | 0x2D–0x38 |
| F1–F12 | 0x3A–0x45 |
| PrintScreen / ScrollLock / Pause | 0x46 / 0x47 / 0x48 |
| Ins/Home/PgUp/Del/End/PgDn | 0x49–0x4E |
| 方向 右/左/下/上 | 0x4F/0x50/0x51/0x52 |
| NumLock / KP ÷ × − + Enter | 0x53/0x54/0x55/0x56/0x57/0x58 |
| 小键盘 1–9 / 0 / `.` | 0x59–0x61 / 0x62 / 0x63 |
| Application / Power / KP=` | 0x65 / 0x66 / 0x67 |
| F13–F24 | 0x68–0x73 |
| 修饰键 左Ctrl/Shift/Alt/GUI、右Ctrl/Shift/Alt/GUI | 0xE0–0xE7 |

> 注意：修饰键以**位**的形式放在报文的第一个字节（bit0=LCtrl … bit7=RGUI），普通键以 usage 数组跟在后面。

### 附录 C：术语表

| 术语 | 含义 |
|---|---|
| HID | Human Interface Device，人机接口设备；键盘/鼠标都属于 HID |
| HID Report Descriptor | 描述设备报文格式与键位映射的二进制结构 |
| usage / keycode | HID 规范里的按键编号（不是字符） |
| 6KRO | 标准键盘报文：最多 6 个普通键同时按下 |
| NKRO | 全键无冲，用位图表示任意多个键 |
| 修饰键 | Ctrl/Shift/Alt/Win 这类"按住生效"的键 |
| 粘滞键 | 点一下锁定修饰键，打完自动释放 |
| 组合键 | 多个键同时按下产生的快捷操作 |
